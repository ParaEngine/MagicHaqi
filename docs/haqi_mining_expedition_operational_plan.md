# 哈奇矿区与星球探险运行手册

本文固定当前版本的数值预算、观测字段与发布验收标准。它不创建新货币，也不改变宿主资产结算权。

## P4：数值预算

### 博物馆套装

当前四个内容包的完成套装加成可以同时生效。宿主在发射远征时把攻击加成应用到伙伴基础攻击；通关后才把掉落加成应用到合规远征材料。

| 系列 | 攻击 | 材料掉落 |
| --- | ---: | ---: |
| 深海回音 | +8% | +12% |
| 远古星核 | +12% | +8% |
| 灼热地心 | +10% | +6% |
| 废土朋克 | +6% | +14% |
| 当前四包总和 | +36% | +40% |

当前四包总和是内容基线，不是由代码强制的永久上限。以后新增内容包前，必须重新评估总和；在没有明确的版本说明和测试前，不得超过攻击 +36%、材料掉落 +40%。

计算顺序：

1. 以伙伴未含矿区 Buff 的 `baseAttack` 为基数。
2. 发射时计算 `round(baseAttack * attackPercent / 100)` 并加入本局攻击。
3. 仅完成且通过的远征可进入宿主结算。
4. 每条合规材料掉落计算 `baseAmount * lootPercent / 100`；小数部分按一次随机判定进位。
5. 装备重复转化为 `stellarEssence`，不参与博物馆材料掉落倍率。
6. 家园珍宝、失败局、未完成局均不经过材料倍率结算。

### 路线芯片与矿区远征

| 来源 | 上限 | 作用 | 不得叠加项 |
| --- | ---: | --- | --- |
| 路线侦测芯片 | 持有 3 枚 | 发射时消耗 1 枚，点亮当次精英或首领路线 | 攻击、材料掉落、经验 |
| 矿区远征货舱 | 单局上限 99 枚原石、99 点研究 | 连续下潜期间暂存；主动撤离、主矿核通关或坍塌后结算 | 远征材料、星币 |
| 矿区远征坍塌 | 压力达到 100% | 原石保留 45%，研究保留 50% | 攻击、材料掉落 |
| 工坊精炼 | 每日 6 次 | 现有矿区内转换 | 远征完成奖励 |
| 工坊出售 | 每日 30 星币 | 现有矿区内出售 | 远征材料、路线芯片 |

路线芯片材料成本固定为：星尘粉尘 `2`、攻击晶核 `1`。请求 ID 已消费时必须返回成功但不重复扣料、不重复加芯片。

主动游玩采用 12 层连续矿区远征：每层在富集矿脉、失稳裂隙、安全前哨、流动补给站、精英矿核与主矿核之间选择。远征进度、货舱、压力和本局模块均保存在该星球的本地矿区存档中，刷新后可以继续。主动撤离保留全部货舱；继续深入会提高收益与坍塌风险。补给站提供强化探矿爪、共鸣钻头或安全锚，它们只影响本局采矿、连击研究或压力，不产生新的常驻货币。

## P6 候选：重复矿石消耗与矿区耐玩性重构

> 本节是下一阶段核心玩法方案。2026-08-13 已完成分叉路线、阶段撤离、不稳定度、四流派协议池、页面构筑交互与失落信标闭环；经济出口、协议扩充与宿主资产协议仍待实施，不属于 P4 当前数值基线或 P5 发布验收范围。

### 问题定义

当前体验存在两个相互关联的问题：

1. 玩家拥有大量重复 R / SR 矿石时，如果缺少配方中的其他指定矿石，已有库存无法参与成长，形成高稀有度死库存。
2. 12 层连续下潜虽然已有压力、货舱、模块和撤离选择，但路线与构筑对操作过程的改变不足，玩家较快看透收益曲线，重复游玩的局间差异偏弱。

P6 的核心原则是“本局所得改变下一局打法”：重复矿石既是收藏后的长期消耗材料，也是进入下一次矿区时选择策略、承担风险和形成构筑的筹码。不得只增加矿石种类、层数或永久攻击百分比来制造内容量。

### 经济出口

P6 不创建新的常驻货币，优先复用现有矿石、星核精粹、星币和路线芯片。

| 出口 | 消耗 | 产出或作用 | 约束 |
| --- | --- | --- | --- |
| 配方材料代偿 | 星核精粹 | 按溢价替代配方中缺少的 R / SR 材料 | 指定矿石始终比代偿划算；UR 及关键成果不得完全代偿 |
| 矿区工程 | 同系列重复矿石 + 星核精粹 | 解锁货舱封装、路线预览、定向钻探、紧急撤离等横向能力 | 以新选择为主，不无限叠加攻击和掉落倍率 |
| 协议芯片 | R / SR 矿石 + 星核精粹 | 制作单局消耗或有限耐久的规则型芯片 | 每局限带 1 枚；效果必须同时包含优势与代价 |
| 协议重铸 | 重复 R / SR | 重置芯片的流派标签或副作用 | 不允许直接刷出无代价的纯数值最优解 |
| 每周研究委托 | 指定系列的重复矿石 | 改变下周矿层生态、首领或定向矿脉权重 | 按系列提交，避免再次卡在单枚指定矿石 |
| 外观收藏 | 重复 SR / 星核精粹 | 矿灯、钻头、货舱和伙伴矿工装扮 | 仅表现层，不制造战力通胀 |

材料代偿应作为缺件保底，不应取代收集。建议先验证“持有配方中的主要材料，只缺 1 种时允许代偿”，再评估完全代偿。工坊必须展示正常配方与代偿成本的差额，让玩家清楚选择的是便利而不是更优收益。

### 单局结构

> 2026-08-13 首版已落地：12 层确定性分叉路线、当前层唯一节点推进，以及第 4 / 8 / 12 层撤离节点。下列搬运、工程与更多节点规则仍属于后续设计。

保留 12 层总长度和第 4 / 8 / 12 层的阶段感，但把固定连续结算改为可预览的分叉路线。每个阶段至少提供两条性质不同的路径，并在汇合前形成一次风险取舍。

```text
入口
├─ 富集矿脉 -> 守卫巢穴 -> 安全前哨
├─ 失稳裂隙 -> 神秘商人 -> 稀有矿脉
└─ 废弃矿井 -> 工程装置 -> 隐藏矿核
				   ↓
			   撤离 / 继续深潜
```

节点职责应明确区分：

- **勘探**：消耗有限扫描次数，提前判断矿脉、敌人或异常。
- **钻探**：在速度、矿石完整度、温度和噪声之间取舍。
- **搬运**：货舱容量有限，现场选择保留、封装、精炼或丢弃。
- **遭遇**：宠物依物种专精处理矿区生物和环境，不只比较攻击数值。
- **异常**：改变后续地图规则，例如提高稀有度并关闭部分撤离点。
- **工程**：修复电梯、开启捷径、降低压力或启动临时精炼设备。
- **矿核**：通过破坏护层、控制温度和应对坍塌完成阶段目标。

### 局内构筑

> 2026-08-13 首个可玩版本已落地：`ProtocolRegistry` 提供爆破、扫描、共振、撤离四流派共 8 个协议，支持三选一、协议入栈及推进、货物、撤离、坍塌钩子；矿区页面已接入协议选择、流派标签、激活协议提示和高危不稳定度警示。首批数值与协议组合仍需持续实玩验证。

首层三选一应扩展为每 2 至 3 层一次协议选择，使一局逐步形成可辨认的流派：

- **爆破流**：开矿快、噪声高、遭遇多。
- **扫描流**：提前识别稀有矿脉，但直接战斗能力弱。
- **共振流**：连续获得同系列矿石后触发复制或强化。
- **撤离流**：频繁封装和运回小批货物，收益稳定。
- **深潜流**：放弃中途撤离换取更高稀有度和矿核奖励。
- **伙伴协作流**：放大宠物物种专精对事件和矿核的处理方式。

协议必须存在组合关系，而不是彼此独立的百分比。例如“高压钻头”提高钻速并加快升温，“冷凝回路”在取得冰系矿石时降温，“共振回收”在连续取得同系列矿石后复制下一块；三者组合后形成玩家主动构建的采矿路线。

### 风险与撤离

> 2026-08-13 首版已落地：`instability`、阶段自动封装货舱、仅关键层撤离、坍塌仅保留封装货物，以及随不稳定度提高的高稀有发现率与坍塌率。具体数值仍需通过实验调整。

矿区的核心张力应是“已经赚到一批货物，是否继续深入”，而不是是否有足够战力通过下一层。

- 第 4、8 层提供明确撤离机会，第 12 层完成主矿核结算。
- 主动撤离保留全部货物；坍塌沿用 P4 的保留比例，工程能力只能改善封装件，不得消除失败风险。
- 爆破、受伤、强行开门和异常事件提高不稳定度；不稳定度同时提高稀有矿脉、精英遭遇和坍塌概率。
- 货舱容量必须迫使玩家选择，不应以当前 99 枚上限让搬运节点失去意义；若调整上限，须作为独立数值实验，不直接覆盖 P4 基线。
- 协议芯片应以规则交换制造开局方向，例如“显示稀有矿脉但隐藏敌人信息”或“SR 权重提高但货舱容量减半”。

### 最小实施顺序

1. **重复矿石保底**：星核精粹代偿缺失 R / SR，先解决库存无法流动。
2. **分叉路线**：实现可预览路线与第 4 / 8 层撤离，不增加新矿石。
3. **协议构筑池**：首批 18 至 24 个协议，至少支持 4 套差异明确的流派。
4. **不稳定度**：把高收益与坍塌、遭遇风险绑定，形成继续深潜的判断。
5. **协议芯片与工程**：让重复 R / SR 在局外改变下一局规则。
6. **委托与外观**：提供周级消耗和非战力长期追求。

首个可玩版本建议只实现“代偿 + 分叉路线 + 中途撤离 + 4 套协议流派”。在证明单局决策和复玩率改善前，不扩充矿石图鉴，不增加永久 Buff 上限。

### 验证指标

P6 进入实验后，应在不记录用户身份和完整背包的前提下补充以下聚合指标：

- 重复 R / SR 的周产出量与周消耗量，以及各出口占比。
- 因缺少单种材料而放弃配方的比例，代偿使用率与正常合成率。
- 第 4 / 8 层撤离率、12 层完成率、坍塌率和平均货舱价值。
- 各路线节点选择率、协议选择率、协议组合完成率和流派胜率。
- 单周主动矿区局数、次日再次进入率，以及同一路线连续重复率。

如果新增系统只提高奖励领取量，却没有改善路线选择分布、撤离决策或再次进入率，应视为未解决耐玩性问题。

## 观测事件契约

当前版本不接入新的遥测后端。若宿主已有事件管道，下列事件以宿主确认后的结果为准；不得由 iframe 的本地存档直接上报资产变化。

| 事件 | 触发点 | 最小字段 |
| --- | --- | --- |
| `mineral_dispatch_started` | 宿主确认派遣状态同步 | `planetId`, `dispatchId`, `mineId`, `petId` |
| `mineral_cooperation_finished` | 协同探矿完成 | `planetId`, `dispatchId`, `hits`, `bestCombo`, `bonusStones`, `research` |
| `mineral_route_preparation` | 宿主处理芯片请求 | `planetId`, `requestId`, `ok`, `duplicate`, `preparationCharges`, `failureReason` |
| `expedition_launched` | 宿主创建远征 run | `planetId`, `runId`, `expeditionId`, `biome`, `routePreparation`, `attackPercent`, `lootPercent` |
| `expedition_settled` | 宿主最终结算 | `planetId`, `runId`, `passed`, `reason`, `baseLoot`, `bonusLoot`, `equipmentDrops`, `homeTreasureId` |

事件禁止包含伙伴名称、用户 ID、完整背包或 iframe 的 localStorage 内容。`requestId`、`dispatchId`、`runId` 仅用于去重与漏斗关联。

建议每周查看：发射到完成转化、芯片请求失败原因分布、重复请求比例、协同探矿平均命中/最高连击、博物馆掉落增量占基础掉落的比例。发现数值异常时，先检查宿主最终结算事件，再检查 iframe 展示状态。

## P5：真实宿主发布验收

本地 Keepwork SDK 服务和真实登录会话恢复后，以下链路是矿区经济扩展的发布门槛：

1. 以真实账号派遣伙伴，刷新后确认派遣、待领取状态与宠物互斥关系保持一致。
2. 领取、鉴定并完成一个矿石系列；刷新后确认博物馆 Buff 在主页和发射参数中一致。
3. 为背包准备星尘粉尘 `2` 与攻击晶核 `1`，熔炼一枚路线芯片；确认宿主只扣除一次材料。
4. 重放同一 `requestId`，确认成功响应但材料与芯片数量都不再变化。
5. 带芯片发射远征；确认本局只消耗一枚、精英或首领路线被点亮，并且攻击/掉落数值不因芯片变化。
6. 分别完成成功局、失败局和未完成局；确认仅成功局写入经验、材料、装备与家园珍宝，且 `runId` 重放不重复结算。
7. 在两个标签页交替执行芯片和发射操作；确认 bridge 修订后的最终值不会回滚、不会双扣或双发奖。
8. 以不同 `planetId` 打开矿区；确认 bridge、localStorage 键、派遣和收藏完全隔离。

在上述验收未完成前，不增加矿区奖励来源、不提高协同探矿上限，也不提高博物馆四包总和。
