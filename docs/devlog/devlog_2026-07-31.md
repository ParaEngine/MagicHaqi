# 2026-07-31 开发日志：远征结算、宠物身份与双端回归

今天的重点是把哈奇星球远征的“可相信的结算”再往前推进一步，并把远征中的伙伴身份与玩家实际携带的宠物档案对齐。完成后，对战、结算和宠物图鉴不再各自显示一个固定的默认伙伴；玩家也拥有了受控的宠物命名入口。

本轮没有执行构建、上传或发布命令。MagicHaqi 是直接在浏览器运行的 ES Module 项目，仓库规则明确禁止以构建命令作为开发验证方式。

## 已完成：结算页使用实际出战宠物

远征启动时，宿主已经会将实际选中的 `selectedPet` 传给小游戏。本轮补齐了结算页最后一段显示逻辑：

- 结算成长面板从固定的“伙伴成长”改为显示实际宠物名，例如“抱抱龙 的成长”。
- 若宠物带有 `imageUrl` 或 `imageSheetUrl`，结算卡使用该宠物资源；没有图片时才回退到宠物 emoji。
- 结算按钮仍保留为“确认返航并写入营地仓库”，清单继续明确奖励由宿主统一结算、同一远征不会重复入库。
- 远征失败弹层会回传失败结果；未击败首领时不会把捕获宠物、材料、装备掉落或家园宝物带回营地。

这里的关键边界仍然成立：小游戏只生成并回传结果报文；奖励、捕获宠物、装备和远征记录真正写入存档，仍由宿主的 `processExpeditionResult()` 与相关存储逻辑负责。

## 已完成：宠物改名规则

宠物图鉴卡片新增“改名”按钮，命名规则已经接入现有弹窗、宠物存档和金币状态：

- 每只宠物首次改名免费。
- 从第二次开始，每次改名消耗 `200` 金币；金币不足时不打开扣费保存流程。
- 名字最长 `6` 个字符，输入框和提交校验双重限制。
- 名字仅允许中文、英文与数字，避免标签、空白和特殊字符进入展示模板。
- 本地敏感词表会拦截常见辱骂、色情、违法和敏感政治词。
- 改名成功后更新 `pet.name` 与 `pet.renameCount`；收费改名同步保存用户金币，保存失败时回滚名字、次数和金币。
- 新名称会被远征选择页、战斗数据和结算页继续使用，因为它们都读取同一宠物对象。

敏感词表是客户端的第一层体验保护，不能替代服务端审核。当前项目没有独立后端审核服务，因此发布环境如接入账号服务，应在服务端继续执行规范化、词库与审计校验。

## 已完成：五步新手任务与可恢复任务抽屉

主应用新增一条独立于“星球诞生”流程的五步成长任务链，由纯状态模块维护完成、奖励领取和收起状态：

1. 查看伙伴属性，奖励 `80` 金币。
2. 完成首次改名，奖励 `120` 金币。
3. 成功摆放第一件非食物设施，奖励 `160` 金币。
4. 完成首次成功远征，奖励 `240` 金币。
5. 打开一条远征历史记录，奖励 `120` 金币。

总奖励为 `720` 金币。奖励仅在对应真实动作完成后自动发放；未完成、重复事件或重复领取均不会增加金币。远征任务只接受成功且实际结算的运行结果，失败、未完成或重复 `runId` 不会推进任务。

任务卡会随当前最早的未完成任务更新。点击“暂时收起”不会删除任务，而是把它缩为右上角的 `★` 抽屉；抽屉显示当前进度与下一项奖励，点击可恢复完整卡片。展开卡片使用约 `70%` 透明度的浅色磨砂背景，而不是对整个组件使用 `opacity`，因此文字和操作按钮仍保持清晰。桌面固定于顶栏下方右侧，窄屏使用 `8px` 右边距和更紧凑的宽度，避免占用画面中央和底部操作区。

游客模式补齐了 `localStorage` 文件存储回退。游客下的宠物改名、用户资料和新手任务进度现在会写入本机档案；登录模式仍使用原有个人页面存储。

## 追加：第五项任务刷新后丢失

针对“完成第四项后刷新账户页面看不到第五项”的反馈，确认任务顺序模块本身会正确把下一项解析为“查看一条远征记录”。问题出在账户资料的写入时机：任务推进原先只调用 `saveUserProfileDebounced()`，用户资料统一延迟 `800ms` 写入；通关后立即刷新时，个人页面仍会加载旧的第四项前档案。

已改为以下规则：

- 完成新手任务、收起任务卡、从任务抽屉恢复任务均立即调用 `saveUserProfile()`，不再等待防抖窗口。
- `saveUserProfile()` 通过统一的即时写入方法先移除同一 `user/profile.json` 的待写防抖快照，再保存最新资料，避免旧快照在稍后反向覆盖第五项任务状态。
- 用户资料载荷保存整个 `settings` 对象，因此 `settings.onboarding.completedTaskIds`、奖励领取记录和抽屉状态会一并进入账户档案。

验证：`npm test` 当前共 `13` 条测试全部通过，其中包括“完成第四个任务后会显示查看远征记录任务”；`js/app.js` 与 `js/storage.js` 编辑器诊断无错误。本机 KeepworkSDK 账号服务仍不可用，因此真实登录账号的云端重载需在可用 SDK 环境中再做一次人工确认。
